# 00 — Conventions · The Multi-Agent Constitution

> **This file is law.** When different AI agents (e.g., Claude Code, Antigravity, Cursor, Codex) disagree on project state, directory paths, or engineering process, the rules here decide. If the rules are ambiguous, the agents **pause and flag it for the human maintainer** — they do not guess.

---

## 1. Purpose
One shared Project-Management brain that **multiple AI agents** read and write — enabling a daily task review, planning, and autonomous execution loop. The core architectural goals are **zero drift** and **universal readability** (everything is plain Markdown + YAML frontmatter; no GUI- or proprietary database locks).

## 2. Multi-Agent Roles
| Actor | Role |
| :--- | :--- |
| **Maintainer** | Human decision-maker & final arbiter. Approves production deploys, billing, security boundaries, and edits to this file. |
| **Orchestrator PM Agent** (Gemini / Antigravity) | The PMO orchestrator. Generates AM daily logs, evening rollups, and executes git synchronization. |
| **Executor Agent** (Claude Code / Aider) | The technical executor. Works inside project repositories, implements code, updates project task state, and authors deep documentation. |
| **Local Assistant** (Hermes / Ollama) | Always-on ambient assistant. Reads the vault via read-only MCP; writes notes into `0_Inbox/`. |

---

## 3. The PARA Vault Structure
* **`0_Inbox/`**: Raw intake. Voice notes, web clips, ideas, bug captures. Anyone (human or agent) can write here.
* **`1_Projects/`**: Active efforts with concrete completion criteria and deadlines. Every active project has a corresponding `PROJECT.md` or specification.
* **`2_Areas_Infrastructure/`**: Long-term standards and operational infrastructure (servers, networks, storage, hardware, backups).
* **`3_Areas_Operations/`**: Standard operating procedures (SOPs), runbooks, incident post-mortems, and security guides.
* **`4_Daily-Logs/`**: Dated daily standups (`YYYY-MM-DD.md`). Captures AM plans, PM rollups, and blockers.
* **`5_Resources_Knowledge/`**: Reference guides, cheatsheets, literature summaries, and bookmarks.
* **`7_Archive/`**: Completed projects, superseded runbooks, and historical archives.

---

## 4. Source of Truth Rules (Drift-Killer)
1. **Repository First**: For implementation code, the project's own repository (`git log`, test suites) is the definitive truth. The vault coordinates; repositories implement.
2. **Task State**: Active project state is tracked in the project's canonical state document (`PROJECT.md` or equivalent).
3. **No Direct Dashboard Editing**: `00-Dashboard.md` is strictly generated by `scripts/generate-dashboard.py`. Neither humans nor agents hand-edit the dashboard.

---

## 5. Invariants for Agents
* **Read Before Acting**: Always read the current day's log (`4_Daily-Logs/<today>.md`) and `00-Dashboard.md` before planning tasks.
* **Atomic Scope**: Agents make focused, test-backed changes. Never rewrite working infrastructure without explicit instructions.
* **Never Commit Secrets**: Secrets belong in environment variables (`.env` or credential vaults), never in markdown notes.
